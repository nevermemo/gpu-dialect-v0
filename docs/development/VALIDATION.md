# Validation strategy

Validation is layered. Choose the cheapest command that can falsify the current claim, then widen only when the touched boundary requires it.

## Command tiers

| Situation | First check | Wider check | Release check |
| --- | --- | --- | --- |
| Validator/lowering/golden change | `cargo xtask check-feature macro` | `cargo xtask check-workspace` | `cargo xtask check-full` |
| Reflection/layout change | `cargo xtask check-feature reflection` | `cargo xtask check-feature gpu-runtime` | `cargo xtask check-full` |
| Loop dialect change | `cargo xtask check-feature loops` | `cargo xtask check-feature gpu-semantics` | `cargo xtask check-full` |
| Result lowering/match | `cargo xtask check-feature result` | `cargo xtask check-feature gpu-semantics` | `cargo xtask check-full` |
| Diagnostic sidecar maps | `cargo xtask check-feature core` | `cargo xtask check-workspace` | `cargo xtask check-full` |
| wgpu runtime/cache/buffer change | `cargo xtask check-feature gpu-smoke` or `gpu-runtime` | `cargo xtask check-feature wgpu` | `cargo xtask check-full` |
| GPU semantic feature | focused macro/golden test + one GPU feature test | `cargo xtask check-feature gpu-semantics` | `cargo xtask check-full` |
| Example-only change | `cargo test -p <example> -- --ignored` | `cargo xtask check-examples` | `cargo xtask check-full` |
| Artifact/export change | relevant example binary | `cargo xtask check-artifacts` | `cargo xtask check-full` |
| Unknown dirty tree | `cargo xtask check-changed` | command it selects | `cargo xtask check-full` if release evidence is needed |

## Evidence tiers

Every status line, task report, and decision that cites evidence names the highest
tier it reached. A tier is claimed only with a run record (command, result, and for
Gpu the device).

| Tier | Claim | Typical command |
| --- | --- | --- |
| Unit | Macro validation, translation, and xtask logic pass without external tools; the declared minimum Rust version compiles every workspace target | `cargo test -p gust-macros`, `cargo test -p xtask`, `cargo xtask lint` (CI), `cargo xtask check-ui`, CI job `msrv` |
| Slangc | The generated Slang compiles to the target | WGSL compile smoke tests, `cargo xtask check-fast` |
| Spirv | Exported SPIR-V passes `spirv-val --target-env vulkan1.2` | `cargo xtask check-artifacts`, `cargo xtask spirv-val <file.spv> --target-env vulkan1.2` |
| Reflect | The D17 layout gate matches the descriptor | `cargo xtask check-feature reflection` |
| Gpu | Readback on a device equals an independent host reference | GPU tests, `cargo xtask check-full` |

Each tier is one command: `cargo xtask test --suite <Tier>`. Unit runs `cargo test --locked -p gust-macros`, `cargo test --locked -p xtask`, lint, docs-check, check-arch and check-ui. Slangc is Unit plus `cargo test --locked -p gust --lib` and `cargo test --locked -p gust --test diagnostics` (the Rust-line annotation of real Slang failures). Spirv is `check-artifacts`, Reflect is `check-feature reflection`, Gpu is `cargo test --locked -p gust-wgpu` (a missing adapter fails), and Full is `check-full`, which also runs `cargo test --locked --release -p gust --lib slang` so that the release-only (`cfg(not(debug_assertions))`) tests such as the source-map fallback run, and `cargo test --locked --release -p gust-wgpu --test mismatch` so that the known-mismatch ledger (`docs/SEMANTICS.md`) also runs with `overflow-checks` off (the Gpu suite runs it with checks on). A suite prints what it does not cover, and a pass of one tier says nothing about the tiers above it.

Label format: `done (Gpu: NVIDIA GeForce RTX 5090, Vulkan, slangc 2026.13.1, <commit>)`.
A software Vulkan driver such as lavapipe counts as `Gpu (software)`, never as
hardware evidence. Expected values come from an independent host reference, never from
the shadow bodies (D04). A missing tool or adapter is a failure for its tier, not a skip.

## Single-stage commands

Workflow commands live in `cargo xtask` (D27); no shell or PowerShell scripts are tracked.

| Command | Use |
| --- | --- |
| `cargo xtask lint` | No tracked `.ps1`, `.psm1`, `.psd1`, `.bat`, `.cmd` or `.sh` file, and no machine-specific path in tracked text. Machine paths include Windows, Unix and WSL home spellings (a Unix home name must be followed by `/`, a quote or the end of the line); two test files may spell placeholder names only. Non-UTF-8 and binary files are skipped, and the summary counts them. Scans tracked files only (`git ls-files`): a new file is not linted until `git add` has staged it (see "What each scan sees" below). Also runs in `verify --mode smoke`, `check-fast`, `check-full` and CI. |
| `cargo xtask docs-check` | Relative Markdown links in project `.md` files (any case of the extension; tracked files plus untracked files that are not ignored; footnote definitions are not links) resolve to project files (anchors, query strings and external links are not checked), no merge-conflict markers in text files, and `docs/DECISIONS.md` ids are unique (also when the repeat is not adjacent) and increasing with the right "Next id". Sees untracked files that are not ignored, unlike `lint`. Same runs as `lint`. |
| `cargo xtask check-arch` | D02 guardrails: per-crate dependency allow-list (`gust-macros` = proc-macro2, quote, syn; `gust` = gust-macros; `gust-wgpu` = gust, pollster, wgpu; `xtask` = none), read from `cargo metadata --format-version 1 --locked --no-deps` so that cargo itself resolves `workspace = true`, `package` renames, target tables and every dependency kind (normal, dev, build). Each dependency is judged by its real package name; an allow-listed one must not be renamed with `package`, use a git source or an alternative registry, or be a path dependency outside `crates/<name>` (a workspace crate must be exactly `crates/<name>`). A manifest cargo rejects, for example an inherited dependency with no `[workspace.dependencies]` entry, fails the check with cargo's own message. The metadata is parsed by a small std-only JSON reader in xtask; no dependency is added. `cargo metadata --no-deps` shows declared sources only, so a root `[patch.crates-io]` or `[replace]` redirect is caught in `Cargo.lock` instead: every locked package named in an allow-list must resolve from crates.io (a redirect to git or to a local path changes the lockfile's `source`), and every workspace crate must be a path package. The lockfile is read by a std-only line reader (no network, no full dependency resolve, which would download manifests for every platform); it is trusted as written because the suites' cargo calls use `--locked` and fail on a stale lockfile. Not checked: transitive dependencies outside the allow-lists, and `[workspace.dependencies]` entries that no checked crate inherits. Also: no `ir`, `*_ir` or `ir/` module or file under `crates/` outside a `future/` path, no SPIR-V library in the compiler crates. A change is a DECISIONS entry plus an edit of `xtask/src/arch.rs`. Needs git and cargo. Sees untracked files that are not ignored, unlike `lint`. Same runs as `lint`. |
| `cargo xtask check-ui` | Compile-fail checks for the wording of `#[diagnostic::on_unimplemented]` on `GpuPod`, `Kernel` and `Run`, and for the errors of typed calls and const layout assertions (see "Runtime, typed-call and diagnostic test targets"). For each fixture crate under `tests/ui/` it runs `cargo check --locked --color never --manifest-path tests/ui/Cargo.toml -p <crate> --message-format json` and reads cargo's JSON diagnostics from stdout. A crate with an `expected.txt` (`key: value` lines, `#` comments) must fail with exactly one error-level message of the crate itself (`target.name` is the crate; warnings, the summary note and other crates' diagnostics are ignored, and a second error is a problem that names it), and that error must satisfy every key. Three keys are required, appear once and match exactly: `code` (`code.code`), `file` (a primary span's `file_name`, relative to `tests/ui`, backslashes read as slashes) and `line` (that span's `line_start`; one span must carry both). A primary span outside the crate's own directory, such as core's `panic.rs` for a `const` panic that a macro generated, is reported at the outermost of its macro call sites (`expansion.span`, recursively) that lies in the crate's directory, so `file` and `line` name the user's `#[gust::gpu]` line there; with no such call site it is reported where it is and cannot match, and `label` is still read from the primary span itself. `message` (any number) is a substring of the error's `message` or of a child message, where the attribute's `note` lands. `label` (any number) is a substring of the label of that same primary span, where the attribute's `label` lands. Unknown keys, repeated single-valued keys, a missing required key and absolute paths are errors. A crate without one must compile, which guards valid code against the attribute. Only the listed keys are compared, not the whole rustc output, so toolchain wording changes elsewhere do not break it. `tests/ui` is a workspace root of its own with its own committed `Cargo.lock` (`--locked` fails loudly when it drifts); it is not a member of the root workspace, so `cargo test --workspace` never builds it. Needs cargo only (no slangc, no GPU); its only dependencies are `gust` and `gust-macros` (and their proc-macro crates). Part of the Unit suite and of `verify` smoke, fast and full modes (`check-fast`, `check-full`). Without `CARGO_TARGET_DIR` it builds under `tests/ui/target` (ignored). |
| `cargo xtask bless` | Reruns the Slang golden tests (`cargo test --locked -p gust-macros golden`) with `BLESS_GOLDEN=1`: a golden whose emitted text differs is rewritten, its line diff printed and its test failed with "golden blessed; review the diff and rerun without BLESS_GOLDEN". Then lists changed fixtures with `git diff --stat`. Exits 0 only when no fixture changed. Review every diff before committing. |
| `cargo xtask test --suite Unit\|Slangc\|Spirv\|Reflect\|Gpu\|Full` | One evidence tier as one command (below). Each suite prints its tier and what it does not cover; a missing tool or adapter fails the suite. |
| `cargo xtask doctor` | Tool readiness. Exits non-zero when cargo, rustc, slangc or the reflection helper is missing; `spirv-val` is reported and required only for artifact and full modes. |
| `cargo xtask doctor --smoke` | Doctor, then the hand-written `vector-add.slang` toolchain fixture compiled to WGSL and SPIR-V in a fresh directory under the cargo target directory, and the SPIR-V validated. It says that the Rust frontend and GPU execution were not run; it is not Slangc or Spirv evidence for generated Slang. |
| `cargo xtask slangc <file.slang> --entry <name> --target wgsl\|spirv --out <path> [-- <slangc args>]` | One slangc compile. Refuses an existing output, fails on a missing or empty artifact, writes `<path>.command.json` (version, arguments, exit code, output SHA-256) and `<path>.compile.log`. |
| `cargo xtask spirv-val <file.spv> --target-env <env>` | SPIR-V length and magic check, then `spirv-val`; prints the SHA-256 and validator version. |
| `cargo xtask test-exact -p <package> --test <target> <name>` | Lists the tests, requires `<name>` exactly once, runs it with `--exact --include-ignored`, and fails unless libtest reports one executed, passing test. Certifies execution only. |

`check-ui` passes `--locked` to each fixture check (a unit test checks the arguments). `check-lints`, `check-workspace`, the Clippy and workspace-test steps and the Fast and Gpu test steps of the verify modes pass `--locked` to cargo, as do `test-exact` and every cargo call of the Unit, Slangc, Spirv, Reflect and Gpu suites, including the two reflection test runs behind Reflect and the example runs behind Spirv (a unit test checks them; Reflect also builds the native helper, and only Spirv runs the examples). Not locked: `cargo fmt` (it has no such flag), the other `check-feature` areas, and the `--ignored` example tests of the Examples and Full modes, so the Full suite is not covered by this statement.

## Runtime, typed-call and diagnostic test targets

What each target proves and the tier it reaches. A tier is claimed only with a run record (see "Evidence tiers").

| Target | What it proves | Tier and needs |
| --- | --- | --- |
| `gust-wgpu` test `limits` (`tests/limits.rs`) | Every over-limit launch (workgroup width, invocations per workgroup, workgroup count per dimension, storage buffer count, binding size) is `Error::DeviceLimit` before any pipeline is compiled or looked up (pipeline cache statistics stay at zero); workgroup count and binding size are checked through `dispatch_buffers`, `dispatch_f32` and `dispatch_u32` (and the workgroup count through a one-node graph); exact-limit launches still run; `with_limits` lowers and rejects a raised limit; the opened device reports wgpu's default limits and `gust_wgpu::DEFAULT_MAX_COMPUTE_WORKGROUPS_PER_DIMENSION`; typed, pool and indirect-arguments buffer creation panic for a hand-written `GpuPod` whose layout is not StorageV1 or does not match Rust's size. | Gpu: a Vulkan adapter and the reflection helper; the tests fail without them. Run by `check-feature gpu-runtime`, by the Gpu suite and by `check-fast` (both run `cargo test --locked -p gust-wgpu`). |
| `gust-wgpu` library tests (`cargo test --locked -p gust-wgpu --lib`) | The workgroup-count constant equals `wgpu::Limits::default()`; the runtime layout assertion accepts `u32`/`f32` and refuses a layout that is not StorageV1, a layout with Rust's size and alignment but a bad field offset, and a StorageV1 layout whose size differs from Rust's; the pure limit functions name the first exceeded limit. The same target also holds tests that open a `HeadlessDevice` and dispatch through the reflection helper (pipeline-cache identity, entry points, buffer identity). | Mixed: the constant, layout-assertion and pure-limit tests need no adapter, but the target as a whole needs a Vulkan adapter and the reflection helper and fails without them, so it is Gpu evidence. Run by `check-feature gpu-smoke`, the Gpu suite and `check-fast`. |
| `gust-wgpu` test `typed` (`tests/typed.rs`) | Typed calls reproduce the semantics fixture and are reusable; the alias contract (one buffer bound twice is accepted read-only and rejected when either side writes, on every path including a batch and a graph dispatch node); `Independent` and the length rules; a read-only buffer where the call binds read-write is a run-time error; hand-built calls and buffers of another device instance are checked against the descriptor at submit; binding-index limits. | Gpu, as `limits`. Run by `check-feature gpu-runtime`, the Gpu suite and `check-fast`. |
| `gust-wgpu` test `graph` (`tests/graph.rs`) | The derived edge sets of the staged-graph and component-pool shapes equal the sets registered before the code was written; the derived set is conservative, not a transitive reduction; a derived node never repairs an invalid explicit node and follows a valid one; `GraphReport` counts derived and declared edges; `run_indirect` needs independent arguments and its arguments buffer is a derived edge of its own; an over-limit node anywhere in a graph is reported before any earlier node compiles; an indirect node ignores a `max_compute_workgroups_per_dimension` lowered to 0 (a direct launch of the same kernel is still `DeviceLimit`) but is still limit-checked for the other limits. | Gpu, as `limits`. Run by `check-feature gpu-runtime`, the Gpu suite and `check-fast`. |
| `gust` library tests in `dispatch` (`cargo test --locked -p gust --lib dispatch`) | The typed call surface against two devices: the recording mock (a test fixture) never executes a kernel body, and the CPU side is the real `gust::cpu::CpuDevice` (since m3.b), on which hand-written test bodies run in safe Rust; backend contract checks (access, layout, device instance, length, aliasing), reusable calls, argument conversions. | Unit-level evidence of the surface and of the CPU backend, not of the GPU backend: no slangc, helper or adapter. They run with the other core library tests (Slangc suite, `check-fast`). |
| `gust` doctests of `dispatch` (`cargo test --locked -p gust --doc`) | A buffer of the wrong element type and a buffer of another device type do not compile, a `Call` with the wrong storage-argument count does not compile, and the control that differs in one place does. | Run by `cargo test --workspace`, by `check-workspace` and by the workspace test step of `verify --mode smoke` and `--mode full` (so by the Full suite). The Unit, Slangc, Spirv, Reflect and Gpu suites and `check-fast` do not run them. |
| Hand-written diagnostics fixture: `crates/gust/tests/diagnostics.rs` and the native case in `crates/gust-wgpu/tests/reflection.rs` | A `KernelDescriptor` literal that never passes through `#[gpu]` (an undeclared identifier in hand-written Slang) still fails in `slangc`, so the line-table diagnostics keep a failing kernel even if the validator rejects every macro-built one. The failure names the marked Rust line on `slang::compile`, `reflect::reflect` and the helper failure site (there through a scripted stand-in for the helper), and a descriptor without a line table reports the Slang line. The reflection test runs the same kind of descriptor through the real native helper. | `diagnostics`: Slangc tier (needs `slangc`; a scripted stand-in replaces the helper). The reflection case: Reflect tier (needs the helper). |
| `cargo xtask check-ui` fixtures `typed-call-*`, `layout-outside-*` | The wording and position of the diagnostics for a wrong element type in a generated call (E0271), a device with no `Run` impl (E0277; `typed-call-no-cpu-twin` is the same-crate production-exclusion proof: `gust::cpu::CpuDevice` has no `Run` impl for a kernel when neither `cfg(test)` nor `--cfg gust_dual` is set) and an outside type whose layout breaks StorageV1 (E0080, naming the field or parameter), matched on cargo's JSON; a valid typed call must compile. A primary span in code a macro generated is matched at the outermost call site in the fixture crate (expansion following). | Unit; cargo only. Part of the Unit suite. |

## What each scan sees

`cargo xtask lint` reads **tracked files only** (`git ls-files`). `cargo xtask docs-check` and `cargo xtask check-arch` read tracked files **plus untracked files that are not ignored** (the files the next commit would contain). A new script, or a new file with a machine-specific path, is therefore not caught by `lint` until it is staged with `git add`, while a broken link or a stray `ir` module is caught before that. Ignored files (`target/`, `generated-wgpu/`, `.ai/VALIDATION.json`) are scanned by none of them.

## Minimum Rust version

The workspace declares `rust-version = "1.90"` (D30, which supersedes the 1.88 in D29: the locked `ordered-float 5.5.0`, pulled in by wgpu-hal, declares 1.90). The CI job `msrv` measures the claim: it installs exactly Rust 1.90.0 and runs `cargo check --workspace --all-targets --locked` (all targets, so test code is covered). It needs no slangc and no GPU and runs no tests, so it is Unit-tier evidence of compilation only. It is not a required check yet. A local run needs a 1.90 toolchain: `rustup toolchain install 1.90.0`, then `RUSTUP_TOOLCHAIN=1.90.0 cargo check --workspace --all-targets --locked`. `cargo xtask check-full` uses the stable toolchain and does not measure the minimum version; `.ai/VALIDATION.json` lists it under `untested`.

## Record policy

Routine checks do not rewrite `.ai/VALIDATION.json`. Use `cargo xtask verify --mode <mode> --record` only when a durable record for a non-full mode is useful. `cargo xtask check-full` records by default and is the release-evidence path. The record carries `git_commit` (the output of `git rev-parse HEAD`, taken before the checks start) and `git_dirty` (true when `git status --porcelain --untracked-files=all` listed anything: modified, staged, or untracked files that are not ignored, whatever `status.showUntrackedFiles` says). Both are `null` when git is unavailable or refuses the repository. A record with `git_dirty: true` is evidence about that working tree, not about the commit. `cargo xtask status` prints them as `commit=` and `dirty=`; a record written before the stamp existed prints `unknown`.

## Required evidence by boundary

- Validator: accepted fixture or single-cause rejection test with a meaningful diagnostic.
- Lowering: reviewed Slang golden plus a source-structure assertion when useful.
- Shader target: WGSL compile smoke in routine tests; SPIR-V validation in artifact/full checks.
- Runtime: real GPU readback against an independent host reference, including partial and multiple workgroups.
- Engine proof: explicit contract first, exact transfer/residency/count assertions, no silent fallback.

## What not to do

- Do not run `cargo xtask check-full` as the first check for a local compiler edit.
- Do not auto-bless goldens without reviewing the semantic diff.
- Do not treat `spirv::validate_structure` as semantic SPIR-V validation; external `spirv-val` owns that layer.
- Do not introduce shared `HeadlessDevice` fixtures until `cargo xtask measure-tests` isolates adapter/device setup as the bottleneck.
- Do not commit regenerated `generated-wgpu/` outputs; full/artifact checks regenerate
	them locally and validate the SPIR-V files before leaving them ignored.
