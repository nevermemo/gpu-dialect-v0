# Decisions and boundaries

Recorded 2026-09-07 from the owner's GUST handoff, earlier reflection deferral,
and independent inspection. Chat research is design input, not proof of code state.

| ID | Decision | Rationale / revisit condition |
| --- | --- | --- |
| D01 | GUST project identity and crate names | The project has matured beyond its prototype name; package and Rust identifiers use `gust`, `gust-macros`, and `gust-wgpu` |
| D02 | Keep syn → Slang vertical slice | Existing real GPU behavior is useful; no custom instruction IR or SPIR-V emitter |
| D03 | Separate implemented, researched, aspirational claims | Engine and graph plans are not a shipped subsystem |
| D04 | No CPU execution contract for shader shadows | Independent test references and intentional future CPU nodes remain distinct |
| D05 | Reflection slice 1 authorized on 2026-09-07 | Explicit compiler JSON inspection and POD cross-checks; missing layout evidence must remain unknown. Runtime ABI expansion and automatic reflection enforcement remain separate work |
| D06 | Fix translation correctness before language breadth | Reproduced tail-return, literal, precedence, and struct-constructor issues |
| D07 | Field-aware struct construction in bounded contexts (supersedes the temporary rejection) | Construct a fresh temporary by field name in source order, then assign the destination once; never overwrite a value while evaluating its replacement. Supported as a `let` initializer and assignment RHS; record updates (`..base`), other expression positions, and nested literals remain rejected |
| D08 | Portable tiers plus capability-gated native paths | Avoid both universal feature claims and permanent bans on native acceleration |
| D09 | Fixed-size elements plus separate dynamic metadata | No nested runtime-sized structured-buffer element layout |
| D10 | Extract a small explicit staged graph (delivered by D15) | Typed ordered batches provided the starting proof; D15 implements the bounded graph without a speculative compiler scheduling framework |
| D11 | Engine proofs before ECS architecture commitment | Pools, dependencies, indirect work, then culling/rendering; no premature mega-buffer |
| D12 | Manual file-based Codex/local-AI handoff | No local model endpoint or concurrent-agent protocol has been provided |
| D13 | Historical non-Git takeover; superseded by owner-initialized Git | Baseline hashes and changed-file manifest record the original takeover, not rollback storage. Git is now available; preserve existing history and uncommitted work |
| D14 | Deterministic local/helper `Option<T>` and `Result<T,T>` lowering | `Option<T>` lowers to Slang `Optional<T>`; `Result<T,T>` lowers to GUST's tagged `__GustResult<T>`. Both are bounded to locals and helper signatures with scalar/struct payloads. Result needs equal payload types because Slang cannot infer an absent type parameter from `Ok`/`Err`. Statement-only exhaustive Result matches with `Ok(identifier)` / `Err(identifier)` block arms are lowered by evaluating the scrutinee once then branching on its tag. Struct/resource values, nested Results, mixed Result payloads, `unwrap`/`expect`, combinators, value matches, and `?` remain rejected. Non-32-bit primitives are still not emulated: WGSL lacks them and the storage ABI stays four-byte |
| D15 | Explicit `StagedGraph` with checked, host-declared edges (T07, 2026-09-07) | Executes D10's "small explicit staged graph". Nodes run in insertion order in one submission; declared dependencies are validated against actual buffer hazards, never inferred or used to reorder. Uploads are encoded copies so they order with dispatches. `BufferBinding::independent_length()` is an opt-in exception to the shared element-count rule for settings buffers and reductions; the strict rule stays the default |
| D16 | `GpuPool<T>` vector-like collection and GPU-derived indirect dispatch (T08, 2026-09-07) | Executes D11's first two engine proofs under the contract in ENGINE_NORTH_STAR. Growth is host-driven, geometric, and a GPU-to-GPU copy of the live prefix; no readback, no shrink, retirement behind the copy fence. Indirect args must be derived on the GPU clamped to the allocation because wgpu silently zeroes over-limit indirect dispatches; every indirect binding is independent-length and non-empty. Freelists, compaction, entity IDs, atomics, and culling/rendering remain future proofs |
| D17 | Enforce compiler-authoritative StorageV1 layouts through a native Slang reflection helper (T06 complete, 2026-09-08) | Supersedes D05's "enforcement remains separate work". `slangc -reflection-json` omits aggregate size, alignment, and stride, so the runtime uses `gust-slang-reflect`, a small C++ program over the Slang API (`scripts/probes/slang-layout.cpp`) that compiles and reflects one linked program and fails on anything outside StorageV1. `HeadlessDevice::compile_kernel` (private, via `cached_kernel`) refuses a pipeline unless names, slots, access, workgroup size, and every nested offset/size/alignment/stride match the descriptor; the executed WGSL is that same compilation's artifact. The helper is a build-time tool requirement like `slangc`, not a Rust dependency; its absence is an explicit error, never a skipped check. Bindings are still macro-assigned (AGENTS: no claim that the macro performs reflection). The CLI JSON path stays as partial evidence. Textures, samplers, uniforms, vectors, and multi-group layouts remain outside the contract until they have their own reflected evidence |
| D18 | Bounded loops: only `for i in start..end` with typed 32-bit integer bounds after rustc/Slang checking (T09, 2026-09-08) | A GPU thread must always terminate and must never wait on another workgroup (AGENTS). An exclusive range has a trip count fixed at loop entry: the end bound is evaluated once into a `__gust_end_N` temporary, the loop variable is an immutable fresh binding (`mut` patterns rejected because Slang's counter would then diverge from Rust's per-iteration binding), and the counter only increments. The macro validates the syntactic shape and the known literal-inference hazard; rustc shadows and Slang still own non-literal type checking in this proc-macro architecture. `break`/`continue` without labels or values are allowed; `return` inside the body is allowed. Rejected with diagnostics: `while` and `loop` (trip count not fixed at entry), `..=` (Slang `i <= end` wraps and spins when `end` is the type maximum; Rust terminates), ranges missing a bound, non-range iterables, tuple/`mut`/`ref` patterns, labels, `break` with a value, `break`/`continue` outside a loop, ranges outside the for position, and an unsuffixed integer literal as the start bound (the loop variable takes its Slang type from the start expression, so `0..n` would be `int` in Slang while rustc may infer `u32`). Bounds are side-effect-free in this dialect (assignments are statements, helpers are pure value functions), so hoisting the end before the start is unobservable. A bounded `while` needs an explicit budget contract and is future work |
| D19 | Reserved, unused. The DX task once labelled D19 is now DX19 (sidecar diagnostic maps) | Owner, 2026-10-23: rename tasks instead of reusing decision ids |
| D20 | Reserved, unused. The DX task once labelled D20 is now DX20 (internal ownership splits) | As D19 |
| D21 | Targets are chosen at build time; CPU becomes a build target (owner, 2026-10-23). Supersedes D04's no-CPU-execution stance | A production build contains exactly one target, a GPU target or the CPU target, so the same kernel never has GPU and CPU code in one shipped binary and there is no runtime CPU fallback. Shadow bodies may become executable under D22. A GPU build with CPU fallback is a possible future option, parked in the roadmap |
| D22 | Semantics contract shared by every target (owner, 2026-10-23) | Integers, booleans, control flow and memory effects are bit-exact across targets. Each float operation has a documented error bound, because GPU float32 is not strictly IEEE (fused multiply-add, denormal flushing, approximate division and transcendentals). Divergences that no diagnostic can prevent go in a known-mismatch file whose entries fail when an outcome changes or a mismatch disappears |
| D23 | Target-specific code uses capability-keyed variants with mandatory coverage (owner delegated the design, 2026-10-23) | Variants are keyed by capability (for example subgroup operations, `f16`, 64-bit atomics) with platform names as aliases. Every variant shares one rustc-checked signature. The macro rejects a crate whose variants do not cover every target in its declared target list, CPU included, like a non-exhaustive `match`. A build profile is a target plus a capability set; the runtime fails clearly at startup when the device lacks the profile |
| D24 | WebGL2 is out of scope for GUST compute (owner, 2026-10-23) | WebGL2 has no compute shaders, storage buffers or atomics. The browser path is WebGPU. Revisit for Breeze |
| D25 | Crate naming waits until publication (owner, 2026-10-23) | `gust`, `breeze` and `hurricane` are taken on crates.io. A package can publish under another name (for example `gust-gpu`) while its library stays `gust`. Decide in M10 |
| D26 | Test builds may contain both pipelines (owner, 2026-10-23) | CPU twins are emitted under `cfg(test)`, which the expanding crate evaluates, and under `--cfg gust_dual` for cross-crate tests and benchmarks; never through a Cargo feature, because features unify across the dependency graph and would leak both pipelines into production builds (D21). A kernel that uses a construct without CPU semantics must opt out explicitly. Same-source CPU-versus-GPU comparisons supplement, and do not replace, independent host references for semantics fixtures |
| D27 | Workflow commands live in `cargo xtask`; no shell or PowerShell scripts are tracked (owner, 2026-10-23) | One cross-platform command surface. A lint enforces it. Native toolchain calls inside xtask (for example MSVC's environment setup on Windows) are allowed in their platform branch |

The original takeover excluded crate renaming; the subsequent naming pass is
recorded in D01. Still rejected: rebuilding the shader backend, automatic
CPU fallback, presenting manual metadata as Slang reflection, unrestricted Rust
acceptance, and using copied research examples as untested portable engine code.

Open decisions: rustc integration and version pinning; source maps; typed inference
policy (struct construction is now bounded and proven, see D07); layouts after
reflection; first engine user's unaided acceptance result; entity storage;
shader/module hygiene; capability manifest schema.
