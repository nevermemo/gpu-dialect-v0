| D17 | Enforce compiler-authoritative StorageV1 layouts through a native Slang reflection helper (T06 complete, 2026-09-08) | Supersedes D05's "enforcement remains separate work". `slangc -reflection-json` omits aggregate size, alignment, and stride, so the runtime uses `gust-slang-reflect`, a small C++ program over the Slang API (`scripts/probes/slang-layout.cpp`) that compiles and reflects one linked program and fails on anything outside StorageV1. `HeadlessDevice::compile_kernel` (private, via `cached_kernel`) refuses a pipeline unless names, slots, access, workgroup size, and every nested offset/size/alignment/stride match the descriptor; the executed WGSL is that same compilation's artifact. The helper is a build-time tool requirement like `slangc`, not a Rust dependency; its absence is an explicit error, never a skipped check. Bindings are still macro-assigned (AGENTS: no claim that the macro performs reflection). The CLI JSON path stays as partial evidence. Textures, samplers, uniforms, vectors, and multi-group layouts remain outside the contract until they have their own reflected evidence |
| D18 | Bounded loops: only `for i in start..end` with typed 32-bit integer bounds after rustc/Slang checking (T09, 2026-09-08) | A GPU thread must always terminate and must never wait on another workgroup (AGENTS). An exclusive range has a trip count fixed at loop entry: the end bound is evaluated once into a `__gust_end_N` temporary, the loop variable is an immutable fresh binding (`mut` patterns rejected because Slang's counter would then diverge from Rust's per-iteration binding), and the counter only increments. The macro validates the syntactic shape and the known literal-inference hazard; rustc shadows and Slang still own non-literal type checking in this proc-macro architecture. `break`/`continue` without labels or values are allowed; `return` inside the body is allowed. Rejected with diagnostics: `while` and `loop` (trip count not fixed at entry), `..=` (Slang `i <= end` wraps and spins when `end` is the type maximum; Rust terminates), ranges missing a bound, non-range iterables, tuple/`mut`/`ref` patterns, labels, `break` with a value, `break`/`continue` outside a loop, ranges outside the for position, and an unsuffixed integer literal as the start bound (the loop variable takes its Slang type from the start expression, so `0..n` would be `int` in Slang while rustc may infer `u32`). Bounds are side-effect-free in this dialect (assignments are statements, helpers are pure value functions), so hoisting the end before the start is unobservable. A bounded `while` needs an explicit budget contract and is future work |
